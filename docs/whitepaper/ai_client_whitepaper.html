✦ 执行摘要 (Executive Summary)

随着生成式人工智能向各行各业深度渗透，政务涉密、国防军工、金融核心与高端工业制造领域面临着前所未有的「数据主权与物理断网安全」矛盾：公网大模型存在不可控的敏感资产出域泄密风险；常规离线工具部署极其繁重、依赖复杂；开源生成式 PPT 方案大多采用不可二次编辑的“图片拼贴”，且配音视频制作成本高昂。

AI-Client 专为彻底解决上述痛点而生。项目以 Rust 独立核心引擎（core）为中枢，深度融合 React 现代化任务工作台（web）与 Tauri 跨平台桌面壳（desktop），全面内嵌 llama.cpp、Python、LibreOffice、Piper 神经网络语音与 FFmpeg 等全套附件运行时（sidecars）。系统交付即包含完整的开箱即用能力，做到“双击即用、物理断网零依赖、原生矢量 PPTX 自由修改、音画同步口播视频一键成片”。

2.1 为什么选择 Rust 构建核心引擎？

  • 零垃圾回收停顿与极低常驻内存：相较于 Electron 等重型技术，Rust 核心在维持长时间大模型交互与并发任务调度时，常驻内存仅需几十兆，杜绝卡顿。
  • 信创 CPU 架构原生跨平台编译：基于 LLVM 后端，Rust 能够无缝编译为 x86_64、aarch64 以及龙芯 loongarch64 原生机器码，完美契合国产信创战略。
  • 强类型安全与进程沙箱管理：Rust 严格的借用检查器与并发所有权模型，确保在频繁拉起多子进程（llama-server、Python、FFmpeg）时绝无内存泄露与僵尸进程。

第三章：核心功能模块深度解析（图文全览）

3.1 任务驱动型 Agent 执行中枢与智能步骤合并

AI-Client 摒弃了传统大模型客户端“仅仅提供聊天窗口”的单一范式，全面拥抱「目标驱动的任务工作台」。用户输入模糊的业务诉求后，Agent 执行引擎会自动开启多阶段推进：

  1. 阶段 1/4（需求分析与大纲架构）：分析材料、拆解逻辑脉络、提炼版式方案；
  2. 阶段 2/4（PPTX 原生生成）：调用 generate_pptx 工具生成高质感 16:9 矢量文件；
  3. 阶段 3/4（音画同步视频渲染）：调用 pptx_to_video 执行矢量提取、TTS 配音与流媒体合成；
  4. 阶段 4/4（交付总结）：归纳产物清单，提供后续编辑建议。
图 3-1：AI-Client 任务执行全景图（展示思维规划、工具调用、状态流转与交付卡片）
✦ 独家创新：相同步骤智能合并算法 (Step Collapsing)
传统智能体在处理批处理操作或多步重试时，UI 往往被刷入几十条重复的“调用工具”与“工具返回”日志，导致关键业务结论被严重淹没。AI-Client 在前端 LogViewer 组件中引入了步骤拓扑折叠机制：对同一 Step 内的连续同名工具操作（如连续调用 read_file 或 write_file），系统自动将其折叠聚合为一个整洁的状态卡片，并在徽标上实时显示子操作执行计数（如 read_file (4次操作)），既保持极简视觉，又支持点击展开微观调试。

3.2 大模型配置与端侧 llama.cpp 自动化编排

AI-Client 提供了高度弹性、多模态的模型纳管层，覆盖从端侧离线推理到本地自建服务器的全场景：

  • 本地 GGUF / ONNX 离线模型导入：用户仅需在界面指定本地 .gguf 文件路径，系统内的 LlamaServerManager 将在任务触发时自动探测空闲端口，按需拉起高性能 llama-server，任务结束后自动回收显存；
  • 本地局域网 OpenAI 兼容端点接入：支持直接对接内网部署的 Ollama、vLLM、Xinference 等大模型服务；
  • 402 余额耗尽人文化诊断与免 API 离线直出：当配置的外部接口由于账户欠费返回 HTTP 402/401 时，系统不再抛出冰冷的代码异常，而是弹出友好诊断卡片，并提供「⚡ 使用内置离线引擎直接生成 PPT (免 API 额度)」快捷按钮，确保用户紧急任务不中断。

第四章：ppt-master 演示文稿与口播视频引擎

4.1 原生 DrawingML 矢量排版体系（告别图片拼接与杂乱堆砌）

与市场上大部分“将 HTML/Markdown 截图贴进 PPT”的假课件工具不同，AI-Client 内置的 ppt-master 生成的是100% 原生矢量 DrawingML 幻灯片。文档中的每个矩形卡片、圆角高光底板、立体阴影、文本框与字号层级，在 Microsoft PowerPoint、WPS Office 或 LibreOffice 中均可自由选中、移动、换色或修改文字。

图 4-1：ppt-master 演示文稿生成实机效果（层次分明、高对比重点大字、优雅现代）

为彻底解决用户痛感最强烈的“文字堆砌、排版凌乱、主次不分”问题，引擎确立了严格的排版设计规范：

  • 单页要点严格控制在 3~4 条以内：若原始材料单节超过 4 条，算法自动启用主题分叶（如“核心定位”、“功能全景”、“应用落地”），严禁信息过载；
  • 该简介简介，该详细详细：标题精炼醒目（4~10字）大字高对比呈现；正文详细展开（20~50字）把背后的工作机制与价值介绍清楚，严禁粗暴截断关键句；
  • 语义感知自适应版式：
    • 4 条要点 → 触发 2×2 四宫格聚焦矩阵（带独立彩条与胶囊徽章）；
    • 3 条要点 → 触发 三列立体特色卡片（并列横向架构，带顶部序号圆球）；
    • 2 条要点 → 触发 左右双栏对比 VS 布局；
    • 数据亮点 → 触发 36pt 超大高对比数值亮点卡片（如 100%、0门槛、3倍提升）；
    • 流程推进 → 触发 横向步骤流转图（圆标与推进指示箭头）；
    • 金句使命 → 触发 居中大字极简愿景页。
